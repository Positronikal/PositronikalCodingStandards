# Documentation & Compliance

### Phase 5: Documentation & Compliance

#### 5.1 Security Documentation
- `SECURITY.md` at the **repository root** — this is the canonical location; do not place it in `.github/` or `docs/`. GitHub recognizes all three locations, but root placement is the Positronikal standard because it is immediately visible to any contributor browsing the repository. The `repo-template/SECURITY.md` provides the required structure; populate per-repo specifics (supported versions, project-specific severity examples) as appropriate.
- README security section with setup instructions
- CONTRIBUTING.md with security guidelines
- Architecture documentation highlighting security design
- Incident response procedures

#### 5.2 Compliance Integration
- SOC 2 preparation documentation
- GDPR compliance notes (if applicable)
- Industry-specific compliance (HIPAA, PCI-DSS, etc.)
- Audit trail maintenance procedures
